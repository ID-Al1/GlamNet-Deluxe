# Owner portal — the page that was missing

## What went wrong, plainly

I described `owner.ts` as "your finance view, as a page instead of a spreadsheet." That was wrong of me. I only ever wrote **backend routes**. A backend route is a door with no handle: it works if something calls it, but there is nothing to click. There was never a page, so there was nothing for you to see.

That's on me, not on you or on Replit.

Two more things I should have said clearly at the time:

**The finance routes were not built.** What actually shipped in `owner.ts` is the verification queue only: list pending artists, approve, reject. The GMV, commission and payout-run routes I wrote were dropped, and they depend on patch 3's database fields anyway (`paidOutAt`, `payoutReference`), which have not been applied yet. So there is no finance view to see either, and there won't be until patch 3 lands.

**Your test accounts were never going to disappear.** Patch 4 hides unverified artists from browse. It does not delete anyone, and it shouldn't. Both accounts still exist and always will unless you delete the rows. What changed is that clients cannot see them.

There is also a third possibility for why you still see them, and it is worth checking first, because it would mean **none of today's work is live at all**.

## Check this before anything else: are you looking at a published deployment?

Replit has two different things running:

- **The preview**, inside the workspace, which runs your current code
- **The published deployment**, at your live URL, which runs whatever code was there the last time you clicked Republish

If you have published Bonisa at any point, that published version is frozen at that moment. Every change from today — the bug fix, the verification gate, the notifications, all of it — exists only in the preview until you republish.

That would explain seeing test accounts in browse perfectly, because the deployed copy has none of the gate.

**Look for the Republish button in the top right of Replit.** If it's there and highlighted, click it. Then check again.

## The page

`owner.tsx` in this folder is the portal. Drop it in and add one route.

**What it does:**

- Lists every artist waiting for verification, with her bio, specialty, location, email and phone
- **Verify** button: approves her, and she immediately gets the WhatsApp and email telling her she is live
- **Needs more** button: opens a box where you type what she has to fix. She gets that message word for word and her status resets so she can submit again
- Flags anyone waiting three or more days, in red. Your operations doc says no application should sit unanswered for more than 72 hours, so the page holds you to your own rule
- Warns you when an artist has no phone number, so you know email is the only way to reach her
- If you are signed in as anyone other than the owner account, it says so and tells you which email it saw, instead of failing silently

**What it deliberately does not have yet:** the finance view. That needs patch 3 first. Once those fields exist I will add a second tab with GMV, commission earned, what you owe artists, and your on-time payout rate.

## How to install it

Upload this folder, then paste:

```
Add the owner portal page from the uploaded bonisa-owner-portal/ folder.

1. Copy owner.tsx to artifacts/glamnet/src/pages/owner/index.tsx

2. Register it in App.tsx alongside the other routes:
   const OwnerPortal = lazy(() => import("@/pages/owner"));
   <Route path="/owner" component={OwnerPortal} />

3. This page must be visible to the owner ONLY. Not artists, not clients, not
   brands. Three layers, all of them:

   a) Server: add an isOwner boolean to the user object returned by login,
      signup and any /me route. Compute it server side by comparing the user's
      email to OWNER_EMAIL. Do NOT hardcode any email address in the frontend
      and do NOT send OWNER_EMAIL itself to the browser.

   b) Navigation: show the "Owner" link only when user.isOwner is true. Every
      other role sees no link at all, and no trace of one.

   c) Route guard: if someone types /owner directly and is not the owner,
      redirect them to /dashboard. The page already handles a 403 from the API,
      but they should not reach it in the first place.

   The API routes are already gated server side, so the data is safe either
   way. This is about the portal being invisible to everyone else, not just
   locked.

4. Typecheck, commit, push.

Then tell me: has this project ever been published to a deployment, and if so
when? I need to know whether the live URL is running today's code or an old
copy.
```

That last question matters more than the page does. If the live site is running a version from before today, then the verification gate is not actually protecting anything yet.
